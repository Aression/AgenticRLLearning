## 一个可操作的定义

本库以 **LLM Agent 的强化学习训练**为核心：策略根据任务历史或记忆选择动作，与外部环境进行多步交互，再用奖励信号更新可学习参数，以提高任务的长期效用。这是工作定义，不是整个社区已统一的术语标准。[来源](https://arxiv.org/abs/2509.02547)

经典 RL 中 agent 原本就是决策主体。近期的 Agentic RL 更多强调语言模型从回答生成器变成工具、网页、代码或其他环境中的行动者。它常适合用部分可观测决策过程建模，但也有完全可观测的简化任务。

## 四个概念不要混淆

| 概念 | 主要变化 | 是否必然更新策略参数 |
| --- | --- | --- |
| Agent 工作流 / ReAct | 提示、编排、工具调用、反馈进入上下文 | 否 |
| LLM reasoning RL | 用奖励优化推理或答案生成 | 是，但不一定有外部多步行动 |
| Agentic RL | 用环境交互回报优化多步决策 | 是，可训练模型、路由器或其他策略组件 |
| 多智能体编排 | 多角色交换信息与协作 | 否；多 agent 不等于 MARL |

ReAct 展示了推理和行动交替的结构，不能仅凭轨迹里有 Thought/Action/Observation 就宣称进行了 RL。R1 说明可验证任务中的推理能力可以通过 RL 提升，但数学答案训练本身不足以证明浏览器或软件工程 Agent 的长时程能力。

## 最小判断清单

1. **策略是什么？** LLM 参数、工具路由器还是固定规则？
2. **动作是什么？** token、完整工具调用、子任务还是整段轨迹？
3. **环境如何反馈？** 工具结果是 observation；正确率等评价才是 reward，两者不必相同。
4. **何时学习？** 训练阶段更新权重，还是推理阶段只追加记忆？
5. **评价什么？** 独立任务成功率、成本和可靠性，而非训练奖励单指标。

## 一个贯穿全库的例子

“找到项目中的 bug，修改并通过隐藏测试”：策略选择读文件、运行命令、编辑和结束；环境返回文件内容与测试结果；最终隐藏测试产生奖励。成功依赖早期定位和后续修改，且无法从当前输出完全知道仓库状态，因此有部分可观测性与信用分配难题。

## 自测

一个固定 LLM 每次失败后把错误写入记忆，下一次成功率提高了。这属于 Agent 的适应性行为；若没有奖励驱动的参数或策略更新，不能据此认定是 RL 训练。下一步阅读 [数学先修](/notes/prerequisites) 与 [MDP](/notes/mdp)。
