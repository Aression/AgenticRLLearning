## 论文要解决的问题

LLM Agent 在流式任务序列中应当复用自身经验，这已是共识。作者指出的分歧点在于**何时**塑造记忆。主流做法是写时策展：任务结束后把轨迹蒸馏成反思、洞察、工作流或技能，推理时按相似度检索。作者主张这有两个结构性代价：一是信息丢失不可逆，被丢弃的细节在后续任务需要时无法找回；二是单一固定产物要服务多种未来查询，而同一轨迹对不同任务可能承载不同教训。两者同源——策展发生在下游任务已知之前。

## 方法

JitMem 把策展推迟到读时。记忆库只存**未抽象的原始轨迹**（任务描述加完整观察-动作序列），不做摘要或技能抽取。新任务到来时：BM25 按任务描述检索 top-k 轨迹；策展器同时读入检索轨迹与当前任务，合成紧凑的任务条件化 payload；冻结的执行器带着 payload 行动；仅当 LLM-as-judge 判定成功时，新轨迹才入库存。payload 本身是临时的，不入库。

训练上只有策展器可训练，用 GRPO：对同一任务采样一组候选 payload，冻结执行器逐一尝试并返回该基准的原生奖励，组内算优势。作者强调的关键性质是奖励与策展动作之间没有中间步骤，时间间隔为零，因此信用分配是即时的，不需要像写时策展（如 SkillOS）那样把相关任务分组来制造延迟信号。训练用固定记忆库（由基础执行器跑训练集、按真值标签保留成功轨迹）以保证可复现，测试时记忆库在线增长。

## 证据与实验

在 ALFWorld、WebShop、τ²-bench 上评测，执行器为 Qwen3-8B、Gemini-2.5-Pro、GPT-5.4。作者报告：RL 训练的 JitMem 相对 RL 训练的 SkillOS 在 ALFWorld 与 WebShop 上分别提升 16.2 与 16.3 个绝对成功率点；未训练的读时变体在同 curator 模型下也普遍优于写时基线，作者据此主张增益主要来自读时任务自适应策展而非 curator 模型强度。消融显示：去掉任务条件、改为存储全部轨迹并标注对错、改为写时蒸馏，各自都会掉点；把检索结果置空后 RL 版退化到未训练水平，作者据此论证 RL 学到的是蒸馏检索经验而非调用参数知识。效率上报告输入 token 与执行步数下降。

需要注意证据边界：以上均为论文自述，本卡片仅基于摘要与正文摘录，**未复现、未核验代码**。作者也承认 SkillOS 的推理设置未完全公开，他们自行做了复现校准，并在 WebShop 上把无记忆基线压到低于其报告值以求保守。

## 边界与未解问题

检索器固定为 BM25，作者自认在记忆库变大变杂时可能成为瓶颈；策展器每任务多一次 LLM 调用；payload 格式按基准手工设计。τ²-bench 无标准训练划分，只评了免训练变体，且 Airline 与 Retail 上记忆方法相对无记忆无显著增益，作者解释为读时策展更适合需要程序性综合的任务。训练库与测试库存在轻微分布偏移，分阶段刷新只带来有限收益。
