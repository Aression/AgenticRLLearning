## 采用混合架构的原因

PARA 将材料按项目、领域、资源和归档组织，适合管理行动；Zettelkasten 强调原子笔记与链接，适合逐步形成理解；Diataxis 区分教程、操作指南、参考与解释，适合让读者找到合适粒度。本库参考这些方法，不声称逐条实现某个唯一标准。

## 目录职责

| 目录 | 用途 | 对应方法 |
| --- | --- | --- |
| `content/` | 可发布的概念、解释、路线与实验指南 | 原子笔记 + Diataxis |
| `data/sources.json` | 去重的一手来源索引 | Resources |
| `research/` | 检索记录、来源核验与调研边界 | 证据层 |
| `inbox/` | 待处理材料，不直接发布 | 捕获入口 |
| `projects/` | 有结果和期限的学习/复现项目 | Projects |
| `areas/` | 持续维护的问题树与评测标准 | Areas |
| `archive/` | 已结束项目与被替代结论 | Archive |
| `templates/` | 论文、概念、实验卡 | 可重复工作流 |

## 内容生命周期

捕获候选 -> 核对原始来源 -> 摘要筛选 -> 精读与概念链接 -> 小实验/复现 -> 定期复核。任何阶段都可以停留，不把“链接访问成功”写成“结论已验证”。新预印本默认标记待精读。

## 每次提交前

保证 id 永久稳定，标题可以修改；保留来源 id 与正文引用；标注更新时间、复核状态和适用条件；新增链接需通过内容校验；构建与浏览器测试通过后再部署。内容删除时处理入链，避免静默 404。

## 维护节奏

每周清理 inbox，选 1–3 篇候选；每月复核实验与问题树；每季度检查来源链接、被替代方法和依赖版本。自动化只运行构建与检查，不自动把抓取的摘要写成已审核知识。

## Git 与个人隐私

源码和原创笔记进 Git；模型权重、原始大数据、密钥和含私人信息的轨迹不进 Git。Vercel 站点公开发布的内容即使来自私有仓库也对外可读。引用原文采用短摘录与链接，不复制整本书或论文。
